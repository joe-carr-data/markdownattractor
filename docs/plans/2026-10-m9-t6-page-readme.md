# Plan — M9: T6 on our own corpora, the page by axis, the README numbers row (drafted 2026-10-26, started on "go M9")

Milestone M9 of the execution plan (`2026-09-benchmark-execution.md` §4 T6, §5 M9, §7): the last published table and the two deliverables that make the programme readable. T6 reruns the T2 method (answer quality, grounding, the three gates, savings only where they pass) on the three corpora the strategy plan fixed as *ours* (`2026-09-benchmarks.md` §2): the golden set, this repository's `docs/`, and the owner's private trading-research repository, the last as **supporting evidence only**, exempt from the reproducibility claim and separated on the page. Together with the DocsQA corpora this gives the break-even curve axis E asks for: source tokens per answer against corpus size, from 117 sections to 23K. The page is then restructured by axis (A–E), with the "where we lose" and "what the model already knew" sections consolidated, and the README gets one numbers row per headline claim, each limited to the gates that passed. The holdout stays sealed; nothing in M9 reads a DocsQA split.

## Decisions carried in

- **Three corpora, named before any number** (strategy §2 "Ours"). `golden`: `evals/golden/docs` (32 files, 117 sections), fictional platform-team notes; the model cannot know them. `docs`: this repository's `docs/` at the commit the freeze names (71 files; the `.markdownattractor/` stores inside are not content and are excluded from the copy); the model knows Rust and Claude Code generalities, never this repository's decisions (rule 0.6, stated per corpus). `private`: the owner's trading-research repository at a commit the freeze names only by its content fingerprint (860 markdown files, ≈ 7.5K sections; the strategy plan said 7,380 at a prior state). The private corpus's **paths, texts, headings, card texts, question texts, reference texts, answer texts and the repository's name or location never enter the repository**: committed artifacts for it carry ids, sha256 digests and aggregate numbers only, every path field is replaced by `<private>` before commit, and `t6.sh archive` refuses to write a committed file that contains its root path, any of its file paths, or any string the secret scan flags. The two public corpora are reproducible from this repository alone: the copies are `git archive <commit> <subtree>`, so a reader rebuilds them from the published commit.
- **Copies, never the live trees.** Each corpus is indexed in a fresh copy under `$RUN/t6/<corpus>/src` with its own store (`backend = claude-cli`, `embeddings = local-small`, as T1's stores), `.mda-pinned` = the source commit (public) or the content fingerprint (private). The working repository's own `docs/.markdownattractor` stores are never read or written by the harness. The private copy is deleted at `t6.sh teardown`; its store stays under `$RUN` only.
- **Cards, committed for the public corpora (rule 0.9).** `mda eval --export-cards` after each public index: `evals/results/own/cards-<mda-version>-golden.json` and `-docs.json` with their provenance sidecars; coverage must be complete (never a carded row below 100% coverage). The private corpus's cards are not committed; its provenance aggregates (count, model, span, list-price usage) are.
- **Questions: 25 per corpus, generated from the corpus, validated by the model panel, no human gate.** Candidates are the corpus's headed sections of at least 200 characters, one per document, in `SHA-256(seed ‖ section id)` order (seed 20260922; T4's rule). For each candidate, Sonnet through `claude -p --json-schema` (a tagged `<section>` payload, the section text only, never the path) writes `{q, reference}`: a question a reader of this corpus would ask, that does not name the file, the heading or the repository, and that the section answers on its own; a reference of at most 80 words stating the facts the section gives. Two deterministic refusals before the panel: the question or reference contains a path component or the document's title; the reference shares fewer than three content terms (lower-cased, stop-words removed, length ≥ 4) with the section. Then the panel (`panel.sh questions`: Fable through `claude -p`, Astra through `codex exec`, blind, the same rubric) judges each surviving candidate on two booleans — *the reference is correct and complete against the section* and *the question is answerable from the section without naming it* — and a candidate is accepted only when both members accept both. Candidates are consumed in seeded order until 25 are accepted; every candidate, verdict and rationale is archived (public corpora: texts; private: ids and digests). `sources` of an accepted question is the section's `path#heading` (hashed for the private corpus) and `relevant` its path, so the question file has T2's shape and `t2.sh` runs it unchanged. The committed question files of the public corpora carry the texts (generated, no third-party text; this is what makes a rerun exact); the private one carries ids and sha256 like a T2 sample, with the texts under `$RUN`.
- **Arms: T2's.** grep (Read/Grep/Glob), mda (its MCP server + search-first rules), qmd (its MCP server on a per-corpus index `t6-<corpus>`, its own skill), graphify (its MCP server on a Sonnet-built graph of a copy of the corpus; where its build does not complete the record says so and the arm is "did not complete", as T2 on Prisma and GitHub Docs; the private corpus has 860 files and graphify's skill asks to narrow above 500 — the headless prompt answers "whole path" as in M2). Every arm launched through `lib.sh arm_launch` with the working-copy overrides (`ARM_CORPUS_OVERRIDE`, `ARM_QMD_INDEX`, `ARM_GRAPHIFY_DIR`), the configuration the preflight probes. No git in Bash (T6 asks documentation questions; T5's equal-evidence condition does not apply).
- **Runs, grades, analysis: T2's, byte for byte in method.** `t2.sh run` (3 runs per question and arm, Sonnet, 12 turns, 600 s, one declared retry, every attempt's consumption summed, every MCP server cold), `t2.sh grade` (Sonnet: 0–6 against the reference; grounding against the whole cited pages with the amended rubric; the page universe is **every `.md/.mdx/.markdown` file under the corpus copy** instead of the dataset's page list, resolved by the same rule: exact path or unique suffix after a leading `<corpus>/`), `panel.sh regrade` 30 answers per corpus and `panel.sh cards` 100 cards per public corpus (the private corpus's card audit publishes rates only), `mda eval --analysis` with the three gates (lower bound ≥ −0.25, mda mean ≥ 4.0, grounding ≥ 95%) and savings only where a pair passes. `t2.sh` gains two environment seams for this and nothing else: `T2_CORPUS` (the corpus directory, replacing `$RUN/<project>`) and `T2_QUESTIONS_FULL` (the materialised texts of a hashed sample when the project is not a DocsQA project); the DocsQA path is untouched (the T2 freeze still checks).
- **Freeze, preflight, archive.** `freeze.sh --protocol final --table T6` writes `evals/results/own/T6/FROZEN.md`: the two public corpora as `<repository commit>:<subtree>` with the subtree's git tree hash and file count; the private corpus as file count, section count and content fingerprint (sha256 over `path‖blake3(content)` in path order — the fingerprint, not the paths); the committed cards; the question files; the harness (`t2.sh`, `t6.sh`, `lib.sh`, `panel.sh`, `probe.sh`, `freeze.sh`, the rubrics); the models requested; the run and analysis parameters; the arms (qmd index fingerprints, graphify graph hashes and completion). `t6.sh preflight <corpus>` is T6's gate: the freeze check, no provider key, the store's card coverage complete, the committed cards reconstruct the public store (a `--no-summarize` index of a fresh copy with `--cards` attached is complete and has the same section count), the question file's hashes (private) or texts (public) match, the private-content leak scan of `evals/results/own/` is clean, and three activation probes per arm on the sample's first questions (traces kept under `evals/results/own/preflight/T6-<corpus>/`). Counted runs refuse to start without a passing preflight bound to the store's hash.
- **Committed** (`evals/results/own/T6/<corpus>/`): `questions.jsonl`, `questions.candidates.jsonl` (every candidate with the panel's verdicts), `manifest.json` (home paths abbreviated; private paths replaced), `grades.jsonl` and `grades.adjudicated.jsonl` (answer text as `answer_sha256`; for the private corpus also the cited-page fields reduced to counts), `analysis.json`, `analysis.adjudicated.json`, `panel/regrade.json` and the members' score files (rationales removed for the private corpus), `panel/cards.json` (public corpora). `t6.sh table` renders the page tables from the analyses and grades, never retyped; the private corpus renders into its own, separately headed table.
- **The page by axis.** `docs/benchmarks.md` is reorganised: a short head (what the programme measures, the five axes, the rules in one paragraph, the headline table of claims and gates), then **A retrieval** (T1 final; the golden-set retrieval table; the latency table), **B answer quality and token economy** (T2, T6), **C freshness** (T4), **D time** (T5), **E cost and size** (T3, the T6 break-even reading), then **Where we lose** (consolidated from T1's section and every table's reading: corpus sizes, projects, comparators, with the numbers), **What the model already knew** (rule 0.6: per corpus, what prior knowledge could contribute and what the arms' traces show), **Not measured yet**, and **Provenance** (every `FROZEN.md`, `TUNING.md`, the runbook sections, the raw logs and traces). The development and exploratory sections (the 2026-09-22 golden A/B rows, the DocsQA development rows, the M2 competitor rows, the tuning loop, the post-stop exploration, the pooled diagnostic, the T2 pilot) move verbatim to `docs/archive/benchmarks-development-2026-09.md`, linked from the axis they belong to. **Every generated table and every "What travels with the table" paragraph moves byte for byte**: `scripts/eval/tests/page-blocks.sh` extracts each generated block from the page before and after and fails on any difference; the T5 table hash of runbook §7.5 still matches.
- **The README numbers row.** One row per headline claim of execution plan §7, limited to the projects and comparators whose gate passed, worded as measured, every number generated by `t6.sh readme-row` from the committed analyses and rows (never retyped) and pasted between two HTML comment markers the test checks: *fewer source tokens at parity* (T2, T6: the pairs whose three gates passed, or "no pair passed the gates: no savings claimed", with the measured medians beside it), *fresh within seconds* (T4: mda save → raw-searchable p50 1.7 s, save → card p50 8.4 s on Prisma, one machine), *time questions correct with less effort at equal evidence* (T5: no pair earns the claim; the correctness point estimates beside it), and the retrieval target (T1: hybrid at or above qmd full on every project's point estimate, every interval including zero). The README's older "Honest benchmarks" bullet is updated to point at the row.
- **Cost and time, estimated before the go.** Index builds: golden and docs minutes, the private corpus ≈ 7.5K sections ≈ $35 list-price at Haiku through the daemon (T3's rate) over 1–2 h. graphify Sonnet builds: golden/docs minutes; the private corpus is the open question (T3: Sonnet never completed on 693+ pages). Questions: ≈ 90 candidates × (1 writer + 2 panel) calls ≈ $5. Runs: 25 × 3 × 4 × 3 = 900 answers ≈ $45 and ≈ 7 h at one job; grading ≈ 7 h; panels ≈ $10. Every call through the owner's logins; list price is reporting only.
