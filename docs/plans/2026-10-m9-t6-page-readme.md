# Plan — M9: T6 on our own corpora, the page by axis, the README numbers row (drafted 2026-10-26, started on "go M9")

Milestone M9 of the execution plan (`2026-09-benchmark-execution.md` §4 T6, §5 M9, §7): the last published table and the two deliverables that make the programme readable. T6 reruns the T2 method (answer quality, grounding, the three gates, savings only where they pass) on the three corpora the strategy plan fixed as *ours* (`2026-09-benchmarks.md` §2): the golden set, this repository's `docs/`, and the owner's private trading-research repository, the last as **supporting evidence only**, exempt from the reproducibility claim and separated on the page. Together with the DocsQA corpora this gives the break-even curve axis E asks for: source tokens per answer against corpus size, from 117 sections to 23K. The page is then restructured by axis (A–E), with the "where we lose" and "what the model already knew" sections consolidated, and the README gets one numbers row per headline claim, each limited to the gates that passed. The holdout stays sealed; nothing in M9 reads a DocsQA split.

## Decisions carried in

- **Three corpora, named before any number** (strategy §2 "Ours"). `golden`: `evals/golden/docs` (32 files, 117 sections), fictional platform-team notes; fictional (prior knowledge is described, not asserted absent; rule 0.6). `docs`: this repository's `docs/` at the commit the freeze names (71 files; the `.markdownattractor/` stores inside are not content and are excluded from the copy); the model knows Rust and Claude Code generalities; what it could know of this repository's decisions is described per corpus, not asserted (rule 0.6). `private`: the owner's trading-research repository at a commit the freeze names only by its content fingerprint (860 markdown files, ≈ 7.5K sections; the strategy plan said 7,380 at a prior state). The private corpus's **paths, texts, headings, card texts, question texts, reference texts, answer texts and the repository's name or location never enter the repository**: committed artifacts for it carry ids, sha256 digests and aggregate numbers only, every path field is replaced by `<private>` before commit, and `t6.sh archive` refuses to write a committed file that contains its root path, any of its file paths, or any string the secret scan flags. The two public corpora are reproducible from this repository alone: the copies are `git archive <commit> <subtree>`, so a reader rebuilds them from the published commit.
- **Copies, never the live trees.** Each corpus is indexed in a fresh copy under `$RUN/t6/<corpus>/src` with its own store (`backend = claude-cli`, `embeddings = local-small`, as T1's stores), `.mda-pinned` = the source commit (public) or the content fingerprint (private). The working repository's own `docs/.markdownattractor` stores are never read or written by the harness. The private copy is deleted at `t6.sh teardown`; its store stays under `$RUN` only.
- **Cards, committed for the public corpora (rule 0.9).** `mda eval --export-cards` after each public index: `evals/results/own/cards-<mda-version>-golden.json` and `-docs.json` with their provenance sidecars; coverage must be complete (never a carded row below 100% coverage). The private corpus's cards are not committed; its provenance aggregates (count, model, span, list-price usage) are.
- **Questions: 25 per corpus, generated from the corpus, validated by the model panel, no human gate.** Candidates are the corpus's headed sections of at least 200 characters, one per document, in `SHA-256(seed ‖ section id)` order (seed 20260922; T4's rule). For each candidate, Sonnet through `claude -p --json-schema` (a tagged `<section>` payload, the section text only, never the path) writes `{q, reference}`: a question a reader of this corpus would ask, that does not name the file, the heading or the repository, and that the section answers on its own; a reference of at most 80 words stating the facts the section gives. Two deterministic refusals before the panel: the question or reference contains a path component or the document's title; the reference shares fewer than three content terms (lower-cased, stop-words removed, length ≥ 4) with the section. Then the panel (`panel.sh questions`: Fable through `claude -p`, Astra through `codex exec`, blind, the same rubric) judges each surviving candidate on two booleans — *the reference is correct and complete against the section* and *the question is answerable from the section without naming it* — and a candidate is accepted only when both members accept both. Candidates are consumed in seeded order until 25 are accepted; every candidate, verdict and rationale is archived (public corpora: texts; private: ids and digests). `sources` of an accepted question is the section's `path#heading` (hashed for the private corpus) and `relevant` its path, so the question file has T2's shape and `t2.sh` runs it unchanged. The committed question files of the public corpora carry the texts (generated, no third-party text; this is what makes a rerun exact); the private one carries ids and sha256 like a T2 sample, with the texts under `$RUN`.
- **Arms: T2's.** grep (Read/Grep/Glob), mda (its MCP server + search-first rules), qmd (its MCP server on a per-corpus index `t6-<corpus>`, its own skill), graphify (its MCP server on a Sonnet-built graph of a copy of the corpus; where its build does not complete the record says so and the arm is "did not complete", as T2 on Prisma and GitHub Docs; the private corpus has 860 files and graphify's skill asks to narrow above 500 — the headless prompt answers "whole path" as in M2). Every arm launched through `lib.sh arm_launch` with the working-copy overrides (`ARM_CORPUS_OVERRIDE`, `ARM_QMD_INDEX`, `ARM_GRAPHIFY_DIR`), the configuration the preflight probes. No git in Bash (T6 asks documentation questions; T5's equal-evidence condition does not apply).
- **Runs, grades, analysis: T2's method, with the T6 rubric adaptation declared below.** `t2.sh run` (3 runs per question and arm, Sonnet, 12 turns, 600 s, one declared retry; the scored row carries the final attempt's metrics and `cost_usd_all_attempts` sums every attempt's cost, every attempt's trace kept; every MCP server cold), `t2.sh grade` (Sonnet: 0–6 against the reference; grounding against the whole cited pages with the amended rubric; the page universe is **every `.md/.mdx/.markdown` file under the corpus copy** instead of the dataset's page list, resolved by the same rule: exact path or unique suffix after a leading `<corpus>/`), `panel.sh regrade` 30 answers per corpus and `panel.sh cards` 100 cards per public corpus (the private corpus's card audit publishes rates only), `mda eval --analysis` with the three gates (lower bound ≥ −0.25, mda mean ≥ 4.0, grounding ≥ 95%) and savings only where a pair passes. `t2.sh` gains two environment seams for this and nothing else: `T2_CORPUS` (the corpus directory, replacing `$RUN/<project>`) and `T2_QUESTIONS_FULL` (the materialised texts of a hashed sample when the project is not a DocsQA project); the DocsQA path is untouched (historical freezes are verified at their frozen source revisions and by their artifact hashes, never against today's tree).
- **Freeze, preflight, archive.** `freeze.sh --protocol final --table T6` writes `evals/results/own/T6/FROZEN.md`: the two public corpora as `<repository commit>:<subtree>` with the subtree's git tree hash and file count; the private corpus as file count, section count and content fingerprint (sha256 over `path‖blake3(content)` in path order — the fingerprint, not the paths); the committed cards; the question files; the harness (`t2.sh`, `t6.sh`, `lib.sh`, `panel.sh`, `probe.sh`, `freeze.sh`, the rubrics); the models requested; the run and analysis parameters; the arms (qmd index fingerprints, graphify graph hashes and completion). `t6.sh preflight <corpus>` is T6's gate: the freeze check, no provider key, the store's card coverage complete, the committed cards reconstruct the public store (a `--no-summarize` index of a fresh copy with `--cards` attached is complete and has the same section count), the question file's hashes (private) or texts (public) match, the private-content leak scan of `evals/results/own/` is clean, and three activation probes per arm on the sample's first questions (traces kept under `evals/results/own/preflight/T6-<corpus>/`). Counted runs refuse to start without a passing preflight bound to the store's hash.
- **Committed** (`evals/results/own/T6/<corpus>/`): `questions.jsonl`, `questions.candidates.jsonl` (every candidate with the panel's verdicts), `manifest.json` (home paths abbreviated; private paths replaced), `grades.jsonl` and `grades.adjudicated.jsonl` (answer text as `answer_sha256`; for the private corpus also the cited-page fields reduced to counts), `analysis.json`, `analysis.adjudicated.json`, `panel/regrade.json` and the members' score files (rationales removed for the private corpus), `panel/cards.json` (public corpora). `t6.sh table` renders the page tables from the analyses and grades, never retyped; the private corpus renders into its own, separately headed table.
- **The page by axis.** `docs/benchmarks.md` is reorganised: a short head (what the programme measures, the five axes, the rules in one paragraph, the headline table of claims and gates), then **A retrieval** (T1 final; the golden-set retrieval table; the latency table), **B answer quality and token economy** (T2, T6), **C freshness** (T4), **D time** (T5), **E cost and size** (T3, the T6 break-even reading), then **Where we lose** (consolidated from T1's section and every table's reading: corpus sizes, projects, comparators, with the numbers), **What the model already knew** (rule 0.6: per corpus, what prior knowledge could contribute and what the arms' traces show), **Not measured yet**, and **Provenance** (every `FROZEN.md`, `TUNING.md`, the runbook sections, the raw logs and traces). The development and exploratory sections (the 2026-09-22 golden A/B rows, the DocsQA development rows, the M2 competitor rows, the tuning loop, the post-stop exploration, the pooled diagnostic, the T2 pilot) move verbatim to `docs/archive/benchmarks-development-2026-09.md`, linked from the axis they belong to. **Every generated table and every "What travels with the table" paragraph moves byte for byte**: `scripts/eval/tests/page-blocks.sh` extracts each generated block from the page before and after and fails on any difference; the T5 table hash of runbook §7.5 still matches.

## Amendments after the Codex pre-mortem (2026-10-26, before any harness code; `docs/reviews/codex/2026-10-26-m9-premortem.md`, 22 findings, all accepted)

The verdict on the first draft was "do not start"; these amendments are what M9 executes, and the harness review before the freeze checks that each was built.

- **Questions (F1–F3).** Candidates are drawn in seeded order over *documents* first (`SHA-256(seed ‖ rel_path)`), then over the document's sections (`SHA-256(seed ‖ section id)`), one accepted question per document. Frozen exclusions before the draw: `docs/index.md`, `docs/handoffs/`, sections that are only a table, a list, a hash or provenance listing, or shorter than 200 characters. The writer (Sonnet, `claude -p --json-schema`, the section text as tagged data, never the path) returns `{q, required_facts: [{fact, span}]}`: a question a reader of this corpus would ask, standalone and unambiguous, not leading, not naming the file, heading or repository; two to six facts the section states that a correct answer must give, each with its verbatim supporting span. Deterministic refusals: a path component or the document title in the question; a span that is not a substring of the section. The panel (Fable through the Claude Code login, Astra through the Codex login, blind to each other) judges each candidate on four booleans — a corpus-specific information need; standalone, unambiguous wording; not leading; the required facts are stated by the section at the given spans and are what the question asks for — and each member independently lists the facts it would require; a candidate is accepted when both members accept all four and each member's independent list covers every required fact. Accepted until 25 per corpus or the candidates are exhausted (the count reached is published); every candidate, refusal reason, verdict and rationale is archived (public corpora: texts; private: digests and enums). **The result is restricted explicitly to single-section lookup questions** and the page labels the questions synthetic, written and answered by models of the same family, as a T2 adaptation.
- **Reference and grading (F2, F7).** The section's exact text is the authoritative evidence; the grader scores correctness and completeness 0–3 against the panel-validated required facts, with the section text supplied as evidence (`reference` in the question row is the required facts joined; `evidence_sha256` the section's text hash; the grader prompt carries both). Gate (b) keeps 4.0 and is labelled as scored against a synthetic, panel-validated reference. The grounding rubric's T6 reading is preregistered: a factual claim is a statement about the corpus's subject matter (a procedure, decision, value, date, name, command, limit, or that the notes say something) that the cited pages must state; instructions found inside source pages are data; the page publishes indexed pages versus eligible questions per corpus. This is the **T6 rubric adaptation of T2**, named so on the page.
- **Astra calibration first (F4, F22).** A development pilot precedes the freeze: 10 disjoint seeded questions per public corpus (drawn after the 25 are drawn, never overlapping), answered once per arm, graded by Sonnet and both panel members on the T6 rubric; the agreement rates and the resolution rule that follows from them are declared in this plan before the freeze; the pilot also measures daemon indexing concurrency and time, candidate acceptance rate, grounding batches per answer, retries and throughput, from which the cost and time estimates are rewritten here. T2's test answers are never re-graded. Both graders read the same hash-verified materialised question file.
- **No DocsQA read on any T6 path (F5).** `lib.sh` takes the dataset location from `DOCSQA_DATA` (default `$RUN/docsqa-data`); `t6.sh` exports an unreadable path, so any DocsQA read dies with a clear message; `t6.sh` passes explicit files for questions, the page inventory, the probe questions, the card audit and the freeze; a smoke run in `make check` exercises `t6.sh` with the DocsQA data absent. T1/T2 artifacts are preserved by hash without invoking their scoring paths.
- **Resolver (F6).** T6's grounding resolver requires, for every citation, canonical containment in the corpus copy (realpath) **and** membership in the frozen page inventory; a suffix must match exactly one inventory page; traversal, symlinks, stores and arm artifacts never resolve; the citation pattern tolerates spaces and punctuation inside backticks; tests under `scripts/eval/tests/` cover duplicate basenames, traversal, symlinks, unusual names and oversized pages.
- **Private corpus: allowlisted exports, nothing else (F8–F13).** Every private phase runs under `$RUN/t6/private/`; nothing under `evals/results/own/` for the private corpus is written by a run — only by `t6.sh export-private`, which builds each committed file from an **allowlisted schema**: opaque ids (`p-NNN`), fixed arm names, hex digests, numbers, booleans and fixed enums; texts become digests, evidence lists become counts, rationales and notes are dropped, paths are replaced; the schema check (`scripts/eval/tests/own-private-schema.sh`, in `make check`) rejects any other key or any string outside the allowed forms, recursively. Full manifests, launch records, traces, error logs, candidates, samples and member files stay under `$RUN`. The private commitment is `sha256(salt ‖ serialisation)` over `rel_path ‖ NUL ‖ blake3(content) ‖ LF` in byte order, salt under `$RUN/t6/private/salt` (never committed); no per-path or per-heading digest leaves the machine. **Two freezes:** `evals/results/own/T6/FROZEN.md` for the public corpora (publicly checkable) and `$RUN/t6/private/FROZEN.md` whose sha256 alone is recorded in the public one; the private table is exempt from independent reproduction and says so. Before every commit on this branch, `t6.sh leak-scan` checks the whole proposed change (`git diff main...HEAD` plus the index and untracked files; file names and decoded JSON string values) against a private denylist under `$RUN` (root-path variants, every relative path, every heading, the repository name, 40-character source excerpts) and prints counts only; public CI enforces the export schema.
- **Freeze inputs and bindings (F14, F15).** The T6 freeze lists: binary sha256 and source commit, the analysis implementation (source paths), embedding model revision and files (`model.sha`), each store's effective `config.toml` and ignore rules, resolved model ids (from the pilot's transcripts), the summarisation prompt and schema, the writer and panel prompts and schemas, arm versions, skills and hook settings, card provenance, the page inventory per corpus (sha256 of the sorted list; the list itself committed for the public corpora), hardware and OS. The preflight compares each copy's inventory and per-file content hashes against `git archive <commit>:<subtree>`; rejects any inherited `.markdownattractor` store or extra file; selects and hashes the T6 card export explicitly (never `evals/golden/cards.json`); verifies section identities, attached cards and embedding completeness against the store. `run` and resume are bound to the freeze, the binary, the corpus inventory, the store hash, the served graph and the qmd fingerprint (T5's pattern); run parameters are constants for counted runs.
- **Attempt accounting stated as it is (F16).** See the Runs paragraph above; `t6.sh grade` refuses an incomplete manifest, and a row whose trace has no parsable result is an error row.
- **Freezes and the runbook (F17).** Historical freezes are verified at their frozen revisions; T6's own freeze and preflight precede every counted row; runbook §7.6 is updated in the same commit as every harness, freeze or table change.
- **Page block inventory (F18).** `page-blocks.sh` covers headings, captions ("Generated by …", "Rendered …" paragraphs), every table and every "What travels with the table" body across the page and the archive; the T5 `tables + caption` hash is re-checked at publication; the docs link check covers moved links.

T6: passing public pairs only, with denominators; the private corpus supporting-only. T4: "Prisma, 20 edits, one machine: raw-searchable p50 1.7 s; card-ready p50 8.4 s" (nearest-rank p50, as disclosed). T1: "Hybrid point estimates met or exceeded qmd full on all projects; all paired intervals included zero." No failed-gate medians in the README.
- **Descriptive reading only (F20).** Corpus-size observations, no causal break-even, no crossover claim; prior knowledge described per corpus.

## Amendments after the Codex harness review (2026-10-26, before the freeze; `docs/reviews/codex/2026-10-26-m9-harness.md`, 29 findings, all applied)

- **Question allocation (F16; second pass F12).** Candidates are judged in seeded order; an accepted candidate is a *counted* question while the counted target (25) is open and its page has no counted question yet; otherwise it is a *pilot* question while the pilot target (10) is open (any page; every candidate is a distinct section); otherwise it is skipped. A corpus publishes with the counted number it reached (the golden set has 27 eligible sections in 19 documents, so at most 19); an empty pilot is tolerated and the calibration rests on the other corpora. `panel.sh questions 25 10` enforces and labels the allocation and refuses other targets on resume.
- **Two blind panel calls (F17).** Each member first lists, from the question and the section alone, the facts a correct answer must give; only then, with its own list fixed in front of it, does it judge the four criteria and each writer fact. Acceptance is unchanged: both members accept all four and every writer fact.
- **Exclusions, exactly (F18).** A section is excluded when at least 90% of its non-empty lines are table rows, list items or hash-like strings (the preregistered "only a table, list or listing"), when it is under 200 characters or unheaded, or, for the docs corpus, when it is `docs/index.md` or under `docs/handoffs/`. Denominators and every rejection are committed (`candidates.summary.json`, `questions.rejected.jsonl`; counts only for the private corpus).
- **Bound resume (F19).** A judged candidate carries its content hash and the rubric/model hash; a change refuses to resume.
- **Calibration record (F11; second pass F3/F17; third pass F12/F13).** `evals/results/own/T6/calibration.json` (from the pilots through the exporter's typed projection: agreement per corpus, the resolved model ids the transcripts and graders returned for every role, throughput, cost, acceptance) is a frozen input validated against its own schema; the declared resolution rule is the id of an implemented policy (today `either-member-differs-by-more-than-one-point-then-panel-mean`, the trigger `panel.sh regrade` executes), never prose; a different rule is implemented and named before it is declared.
- **The commitment (F15)** is `sha256(salt ‖ rel_path NUL sha256(file bytes) LF …)` over the inventory in byte order, salt under `$RUN`; the earlier "blake3(content)" wording is superseded.
- **Exports and the scan (F1–F6).** The private export schema is field-specific and fixed in code (no learned literals, no schema file); `digest-questions` is the one serializer of the committed private question file; `leak-scan` reads the proposed commit's blobs and refuses binary files; the collision filter uses the merge-base with `main` and never exempts a path or a name.
- **Bindings (F7–F10, F12–F14; second pass F1, F9–F11).** The freeze refuses to write when any value failed or is empty; the preflight requires cargo's own `--locked` executable to carry the frozen hash; every arm's serving copy is compared whole-tree with its source; SQL comparisons run through checked variables. Counted runs refuse every runner override and take the preflight's certified arm set; the preflight rebuilds the binary `--locked` and requires the frozen hash, compares graphify's serving copy with the archive, checks card equality and embedding completeness on the reconstruction, and re-checks the private freeze against its published digest; the freeze hashes the live graph, skill, hook settings and qmd collection file, each store and its config, every value computed under a failing check.
