# v0.3 — a clear advantage: trust first, then change-impact review (2026-11-15)

Owner's objective (2026-11-15): "create a project that beats any existing solution and provide clear advantage", with no outside helpers and as soon as possible. This plan replaces the growth plan's Phase 0 video work as the active plan; the launch tasks of `docs/plans/2026-11-growth-launch.md` resume in Phase D here.

Sources: a Codex strategy pass (fresh thread, read-only, 2026-11-15; it verified the benchmark page and the competitors' documented capabilities on the web), three Codex passes on demo takes, a throwaway contradiction spike, and `docs/benchmarks.md`.

## Where we stand (from the published benchmarks, no new measurement)

- **Ahead:** search latency against qmd (T1: under a second against 42–47 s on three corpora); save to raw-searchable p50 1.7 s, to card p50 8.4 s (T4).
- **Level:** answer quality against grep, qmd and graphify; one edge, +0.28 against grep on this repository's `docs/` (T6, interval [+0.04, +0.56]).
- **Behind:** grounding on the golden set, **89.6 % for mda against 97.9 % for grep, qmd and graphify** (T6: 5 ungrounded rows of 48 against 1; "mda's answers, written from a card and the opened section, embellish more often"; one of the five was a last-updated date the page does not carry). Setup: a key or a local model before the first card. Full-answer time against grep on T4 (17.9 s against 7.4 s).
- **Not established:** fewer source tokens at parity (G3).
- A product whose claim is trust scores lowest on trust on its own demo corpus. That is fixed before anything is added.

## The bet

A pre-built index beats search-and-read only where one read cannot know the answer. The bet is **change-impact review**: when a section changes, find the other sections that still state the old thing, and show both passages with their lines and dates. Positioning if it passes its gate: "Change a decision. Find the docs that still describe the old behaviour."

Why this one: it has a trigger (a change), a bounded search (the changed section's neighbours) and an action (review two passages), and it uses what the index already holds: the watcher, section hashes, history, evidence-checked extraction. The spike (2026-11-15, lexical candidates and a Sonnet judge): 0 real contradictions in 297 judged pairs on uv, FastAPI and Backstage docs, 1 real in 57 on this repository's docs (the charter's "no API key", fixed in PR #71). So: value on working docs, none as a stunt on polished ones, and whole-folder scanning is the wrong shape; a change is the right trigger.

Known weakness: a prompt that compares two passages is easy to copy. The advantage has to be low noise, measured.

## Rules for this plan

- No human gates and no outside reviewers: evidence comes from public git history and the Fable + Astra panel. Every claim still needs a gate.
- Each phase has a stop rule. A phase that fails its gate ships nothing under a claim.
- Small releases: each phase ends in a release.

An author's audit, not an adjudication: reading the grader's notes on the answers that lost a point, the notes say the required facts were present and dock details "not in the supplied evidence" (the correctness grader sees only the section a question was written from; the grounding grader sees the cited pages). Whether each such detail is true was not checked independently. Iteration 2 is retained for its narrower answer scope, a design judgment within the two-iteration stop rule. Docs correctness returns within the 0.1 tolerance while golden correctness remains below it; these development results do not establish an overall quality improvement. After the Codex review of PR #74, rule 5 was reworded so that it cannot be read as dropping caveats that matter; that wording is what the counted run measures.

### Phase A — the counted run, specified before it is run

An mda-only rerun cannot isolate the contract's effect from time, grader and extractor differences. So:

- **Arms, under one freeze:** grep, qmd, graphify, mda with the contract (this tree), and **mda with the old contract** as a control (the v0.2.1 binary and its skill), on the October corpora, stores and questions, three runs each.
- **Grading:** Sonnet with the T6 rubrics, unchanged, so that every arm and the October table are graded the same way; the panel on a seeded sample of 60 answers per corpus stratified over the five arms, blind to the arm, with T6's resolution rule; its first member is Opus 5.5 here, not Fable (the owner's choice, 2026-11-15, for usage), its second Astra as before. (Amended before the freeze, 2026-11-15: the first draft of this list had the panel on every mda answer and three declared rubric readings — supported extra facts, labelled index dates, CLI/MCP tool names. Changing the rubric would break the comparison with the control and with October; the control arm under the same rubric is what isolates the contract, so the rubric stays as it is and those three cases are reported by cause, not regraded.)
- **Analysis:** paired, per question, the three runs kept within the question, with intervals; runs are not treated as independent questions.
- **Gates (unchanged, fixed now):** new-contract mda grounding ≥ 95 % on the golden set and not below the old-contract control on docs; correctness not lower than the old-contract control by more than 0.1 on either corpus (paired mean).
- **Disclosed:** these questions guided the wording, so the run is not held out; the result is published as such, beside the October table.

The counted run under a new freeze follows; nothing above is claimed.

## Phase C — change-impact review (target: 10 working days) → v0.3.0

- [ ] Design in this file (appended), an ADR for the public surface, a Codex design pass before code.
- [ ] Candidates for a changed section: explicit links, shared identifiers and entities, embedding neighbours, lexical neighbours; capped.
- [ ] Judgment by the summarization backend: `supersedes`, `conflicts`, `related`, or abstain when scope, version or authority is unclear. Both passages quoted; a finding whose quotes are not in the sources is dropped (the cards' rule). Newer is not treated as right: the output states dates and leaves authority to the reader unless a passage says it replaces the other.
- [ ] Surfaces: `mda check [--since <revision>]` (report, `--json`), a watcher event after a save, an MCP tool. Read-only; nothing is written into the user's files.
- [ ] Evaluation set without outside people: (1) mined from public repositories' git history — a commit changes a statement in one markdown file and a later commit makes the matching correction in another; the first commit is the change, the second file is a labelled affected document; (2) the same number of ordinary changes with no later correction, as negatives; (3) labels confirmed blind by the Fable + Astra panel. Frozen before the first scored run.
- [ ] Baseline: Claude with grep, file reads and git on the same revision range, the same model and budget, told to find documents the change left out of date.
- **Gate:** alert precision ≥ 90 % (panel-confirmed), recall ≥ 70 % of the mined affected documents, and recall not below the baseline's at no more than its cost.
- **Stop rule, checked on day 3 of the phase:** fewer than 15 natural cases found across at least 5 repositories, or precision below 80 % after two prompt iterations → stop Phase C, record the result in `docs/benchmarks.md` as a negative, and go to Phase D with the product of Phases A and B.

## Exit criteria

- Phase A's result is published, pass or fail, and v0.2.2 is released.
- A first search with no credentials works in under 2 minutes (Phase B gate).
- Phase C either passes its gate and ships as v0.3.0, or is stopped by its rule with the negative result published.
- The launch window is run with a demo made only of real output and claims that passed their gates.

## Not in this plan
