# Codex design pass — change-impact review (2026-11-17)

Reviewer: Codex (`gpt-6-astra`, fresh thread `01a1eae9-3c12-74c3-8f35-3f181d6510b1`, no write access requested, through the `codex:codex-rescue` companion; no nested `codex exec`). Subject: Phase C design v1 in `docs/plans/2026-11-v0.3-clear-advantage.md` and the draft ADR-0009, before any code.

**Verdict:** "Rework — before code, fix (1) scope-aware verdicts and three-way evidence, (2) snapshot/identity/cache correctness, and (3) the frozen scoring and cost contract for a reduced C1."

## Findings and triage (14: 6 High, 6 Medium, 2 Low; all accepted)

| # | Sev | Finding | Triage (design v2 in the plan) |
|---|---|---|---|
| H1 | High | Verbatim quotes do not establish a shared scope: a v1 guide, a changelog, an archive, a template or an example legitimately keeps the old statement; front matter with the version may never reach the judge. | **Accepted.** An alert is a *possible* inconsistency under a demonstrably shared scope; the judge receives path, heading path, front matter and the document's opening for both sides and abstains when scope cannot be shown; the listed cases go into a fixed correctness suite before prompt tuning. |
| H2 | High | `supersedes` could quote only the before text and the candidate (two agreeing passages) and overstates authority. | **Accepted.** Separate `before_quote`, `after_quote`, `candidate_quote`, each checked against its own snapshot; verdicts renamed `possibly_outdated` and `possible_conflict`; `supersedes` deferred until it has its own evidence of authority. |
| H3 | High | No freshness contract: a just-saved or never-indexed file, or a candidate already fixed on disk, gives a missed change or a false alert. | **Accepted.** Revision pinned once; raw index synced before the review; participating files re-read before printing, with `stale_during_review`; missing coverage is never shown as a clean review. |
| H4 | High | The cache key omits inputs that change the verdict (path, scope); hash-only findings lose identity. | **Accepted by cutting.** C1 stores nothing (no cache, no findings, no schema change). The later cache is keyed by a hash of the whole request with document identity beside content hashes (ADR-0009 follow-ups). |
| H5 | High | Mining gives hypotheses, not ground truth; precision, recall and their edge cases are underspecified. | **Accepted.** The panel confirms each mined pair from evidence at A only; rejected or split pairs are dropped and counted; precision over deduplicated alerts, all adjudicated; recall named *mined-label recall*; partial runs, caps and abstentions count as misses; ordinary commits are unlabelled; the lexical bias is stated in the result. |
| H6 | High | Logging every call does not bound spend: concurrent budget reads, retries, usage lost on failure variants. | **Accepted.** The new call's result carries usage on every variant; every attempt logged; pairs, retries, input, output and time each capped; calls sequential; the budget check is described as a check before each call, not a strict ceiling. A shared transactional reservation with the daemon is deferred to C2, where the daemon starts spending on reviews. |
| M1 | Medium | Pairing by heading path and occurrence breaks on inserted duplicates, renamed headings, moved sections, renamed files. | **Accepted.** Unchanged hashes pair first, then unique heading paths; everything else is `not_reviewed` with a reason and a count, never an addition. |
| M2 | Medium | Git comparison needs its own contract: root below the top level, non-ancestor revisions, CRLF, and not ADR-0008's eligibility. | **Accepted.** Commit id resolved once, repository prefix applied, non-ancestors refused, line endings normalised for comparison only, each git failure reported distinctly from zero findings. |
| M3 | Medium | Retrieval and cap order unspecified; FTS query built from file content; the prefix `*` survives escaping. | **Accepted.** Bounded term extraction, quoted literals with no prefix operator, common-term cut-off, deterministic fusion, two sections per document, round-robin judgments across changes, counts for retrieved, cut and judged; candidate recall measured before judging. |
| M4 | Medium | The backend method needs an object-safe contract; `Unavailable` was overlooked; prompt isolation for three passages. | **Accepted.** One request/result envelope, implemented for all five backends, tools disabled on `claude-cli`, passages delimited as untrusted data. |
| M5 | Medium | Future isolation and cost fairness need executable checks. | **Accepted.** Per-case clone verified to hold nothing after A, no remote or network, index built only from A, no carried caches; marginal check cost compared uncached, indexing cost apart; prior familiarity of models with public repositories disclosed. |
| M6 | Medium | 15–30 cases support a pilot, not a stable 90 % claim; splitting by pair leaks. | **Accepted.** Split by repository; minimum 8 confirmed cases and 8 alerts in the test half or the gate is *unmeasured*; intervals printed; the stop rule counts *confirmed* cases; the claim is worded as feasibility. |
| L1 | Low | "Verbatim" conflicts with normalised-substring validation. | **Accepted.** Normalisation only locates the evidence; the output renders the exact source slice; empty or ambiguous matches are rejected. |
| L2 | Low | C1 needs explicit cuts to fit a week. | **Accepted.** C1 is lexical plus links, pairwise judgment, CLI and JSON; the rest is listed as deferred in design v2. |
