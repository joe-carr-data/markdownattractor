## 1. Packet

The five questions of the M1 review prompt: (1) does `score_arm` apply exactly the eligibility, split, holdout sealing, page rule and metrics of the store's rows, with the edge cases listed; (2) what could make a reconstruction from the committed cards differ from the original store, and is "identical" sound; (3) can a run against changed inputs slip through the freeze and the preflight; (4) does the probe's activation assertion prove the tool was used; (5) missing tests.

## 2. Findings (Codex, condensed; file:line against `af57e8e`)

| # | Sev | Finding | Codex fix |
|---|---|---|---|
| F1 | High | An interrupted preflight can persist `passed: true`: `finish` looks only at the `failed`/`skipped` counters, not at the exit status or whether every check ran; `--arms ""` runs no probes and passes; a setup failure leaves an old passing report looking current. | Capture `$?` in the trap, a completion marker, an explicit required-check list from the frozen arms, unexecuted checks recorded, failure accounting before setup. |
| F2 | High | The freeze does not establish that a checkout's content matches its pinned commit: `.mda-pinned == HEAD` plus a Markdown file count lets in-place edits (Markdown or the support files `Read` can open) through; the effective `config.toml` and `.git/info/exclude` are not frozen. | Verify tracked content and account for untracked evidence; freeze the effective configuration and ignore inputs; reconstruct from the verified commit plus declared additions. |
| F3 | High | `model_sha` hashes regular files only: the snapshot symlinks the loader actually opens are not listed, so a retargeted link changes what is loaded without changing any hash. | Hash each artifact through its snapshot path with its link target and resolved content; reject external targets; fail on broken links. |
| F4 | Med | Building the checkout does not prove `$MDA` is the resulting executable (a stale binary of the same version passes); `.cargo/config.toml` is missing from the code paths. | Take the executable from Cargo's output, hash it, `--locked`; add `.cargo`. |

| F7 | Med | The reconstruction drops ingestion inputs (the original `config.toml` is copied aside but never applied; `.git/info/exclude` gone with `.git`) and ignores `rsync` and `mda embeddings` failures; no inventory comparison. | Apply the frozen configuration, fail on copy errors, compare document/section inventories. |

Answers, condensed: (1) parity holds for valid canonical paths (same `eligible`, split default, holdout sealing, `pages_of`, `score_pages`, denominators); an explicit empty list scores zero and is counted but is not `missing`; the scorer trusts the driver's `truncated`; external `fetched` counts entries while the store's records the requested depth. (2) Export deduplicates by hash and sorts; ties break by section id, recency is off, provenance does not affect ranking; remaining risks are the shared-hash embedding context (the lowest section id's title and heading) and the ONNX batch composition, for which the code establishes no bitwise guarantee: "identical" is a controlled-environment acceptance test, not a universal proof, and the Rust test covers cards only. (3) F1–F4, F8, F9; `deny.toml` and `Makefile` do not change a number; later attempts overwrite published traces. (4) The assertion proves a request was emitted, not a successful execution; `question_text` ignored its project argument and did not require a single match; a holdout id could be probed. (5) A scorer matrix over identical rankings, reconstruction with shared hashes and tied scores, preflight failure injection, freeze identity cases, probe fixtures, output-safety cases.

## 4. Patterns → rules

- **A gate's report says what did not run.** A check that was skipped or never reached is a failure in the report, and `passed` needs the script's own exit status and a completion marker, not just counters.
- **Hash what the loader opens, not what the directory lists.** Symlinked artifacts are listed with their target and the hash of the resolved content.
- **Regeneration is done from archived observations, never by searching again.** A results file carries enough of the ranked list (ten pages) to recompute every metric it reports.
- **A run's evidence of tool use is a successful tool result matched to its call**, not the call.

## 5. Follow-ups

- Hash the whole permitted evidence tree of a checkout (tracked files through `git ls-files -s` is implied by a clean status; untracked support files are refused) if an arm is ever given untracked material.
- Preflight failure-injection shell test (M5, with the harness failure matrix).
- Per-attempt immutable copies of the published traces already exist under the attempt directory; the published path is the latest attempt.
