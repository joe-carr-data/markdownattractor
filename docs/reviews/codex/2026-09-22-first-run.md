Answers, condensed: (1) the leak routes are F1/F2 plus TOML parse errors quoting config lines through `store.error` and doctor details; (2) no deferred-transaction deadlock, but the deadline does not bound the store calls themselves, `k = 1` returns the lexical winner rather than the card's own section, and the hook/restart/JSON paths behave as designed; (3) the grep does match `toml::to_string_pretty`'s `nudge = false`; it is not a parser (quoted keys, multiline strings), the CLI tests `exists()` where the hook tests `-f`, and local `on` cannot override global `off`; (4) a directory argument is explicit root selection, symlinked directories are followed as the new root, and F7 is the real consequence; (5) hostile diagnostics fixtures, first-run timing cases, hook-plus-launcher tests, nested roots, populated `cost` output.

Not changed, with reason: the hook's grep stays a grep (a TOML parser in a 5 s `PreToolUse` hook is not worth it; `mda nudge` writes the canonical form and the design doc says quoted keys are not recognised); local `on` does not override global `off` by design (`--global` is the wider switch; `mda nudge` prints both states and the effective one).

## 4. Patterns → rules

- **A diagnostics bundle is an allowlist, not a redaction pass**: export named fields you chose, and push every free-form string through one scrubber. Replacing the home prefix is not redaction.
- **Counts must share a unit before they are compared**: `sections` are rows, `summarized`/`pending` are hashes.
- **A hook and the binary that serves it resolve every path the same way** (`MDA_MODEL_DIR`, `MDA_NUDGE_FILE`): one precedence, written down once, tested in both places.
