# Codex design pass — git-aware times (2026-11-10)

Reviewer: Codex (`gpt-6-astra`, fresh read-only thread, through the `codex:codex-rescue` companion; no nested `codex exec`). Subject: design v1 of `docs/plans/2026-11-git-times.md` and its draft ADR, before any code; the recency change in the working tree.

**Verdict:** "Rework. Resolve freshness, snapshot validation, occurrence semantics, and daemon scheduling before implementing the dating pass." Suggested cuts: ship the recency default independently; start with explicit post-index dating; fall back wherever line correspondence cannot be proved; keep observation times immutable; include cancellation and revision-aware invalidation from the start.

## Findings and triage (15: 5 High, 8 Medium, 2 Low; all accepted)

| # | Sev | Finding | Triage (design v2 in the plan) |
|---|---|---|---|
| 1 | High | `git` provenance is not a freshness marker: rows already dated never become eligible again, so rewritten history or a branch switch with identical text keeps stale dates. | **Accepted.** Each document records the revision and blob it was dated at; a pass re-dates a document when `HEAD` moved and the path changed between the two revisions, or the old revision is no longer reachable. |
| 2 | High | The pass can write historical dates onto newer content (another Engine re-indexes the file between blame and the write). | **Accepted.** Compute outside any transaction; apply in a short `IMMEDIATE` transaction that checks the document's content hash, the section ids, hashes and line ranges, and the dating state it read; otherwise discard. |
| 3 | High | Running inside the daemon's rescan blocks saves, replies and cancellation. | **Accepted.** Dating runs on its own thread with its own store connection, per-document short writes, a per-pass time budget and cancellation; a test measures save-to-raw latency while a pass runs. |
| 4 | High | "Tracked and clean" does not prove blame describes the indexed lines (smudge/clean filters; CRLF). | **Accepted.** A file is dated from git only when its working bytes equal the `HEAD` blob exactly (`git hash-object --no-filters` against `git ls-tree HEAD`); filters and CRLF checkouts fall back to filesystem times, documented. |
| 5 | High | Hash-preserved dates conflict with per-occurrence blame dates (duplicate sections; moved sections); incremental results differ from a clean rebuild. | **Accepted.** Times describe an occurrence: a dating pass dates every section of an eligible document from blame, so the result equals a clean rebuild; upsert's keep-time rule matches by (hash, occurrence number) instead of hash; plain blame without `-M`/`-C`; dates never cross documents. |
| 6 | Medium | A commit alone triggers no refresh (`.git` events are ignored; no periodic rescan; single-file indexing bypasses `index_root`). | **Accepted.** The dating thread polls `git rev-parse HEAD` on an interval and runs when it changes; a single-file index queues that file for dating. |
| 7 | Medium | Creation, fallback, rename and `time_source` transitions are underspecified. | **Accepted.** v2 states each transition; `first_seen_at` stays observation time; `time_source = "filesystem"` makes the pass restore file times on git-dated rows. |
| 8 | Medium | Author time is not "last changed in this repository"; future author dates; ancestry order vs min/max. | **Accepted.** Defined as *authored* time, capped at the commit's committer time; created = minimum, changed = maximum author time over the path's commits; the `--since` documentation says so. |
| 9 | Medium | Timeline events (observation) and content dates (git) are different clocks. | **Accepted.** Events stay observation history and are never backdated; `docs/design/search.md` and the card output name the two clocks. |
| 10 | Medium | The blame/parser coordinate contract needs acceptance tests. | **Accepted.** Blame's final-file line numbers against the parser's one-based inclusive ranges; tests for front matter, excluded MDX imports, heading-only sections, CRLF fallback, a missing final newline; the deletion limitation documented with the time filters. |
| 11 | Medium | Repository identity and paths: root below the top level, `-z` parsing, nested repositories and submodules, worktrees, case-only renames, symlinks, sparse checkouts. | **Accepted.** Paths from `ls-tree` relative to the root; `-z` everywhere; `:(literal)` pathspecs; a file not in the root repository's `HEAD` tree (submodules, nested repositories, untracked) falls back; only present, indexed, `safe_join`-validated files are dated. |
| 12 | Medium | Benchmark protection is narrower than "the replay stays reproducible"; MCP launches do not set `MDA_NOW`; the recency default changes fresh agent runs. | **Accepted.** No dating on reads, opening the store or MCP; a subprocess test with a full clone under `MDA_NOW`; the recency change is disclosed as affecting fresh runs (ADR-0007), not regenerations. |
| 13 | Medium | No pass-level cost or retry policy for large repositories. | **Accepted.** Pass budget and cancellation; failures remembered per (path, revision, blob) so a pathological file is not retried every pass; batching of history walks deferred until measured on a large repository. |
| 14 | Low | The additive migration needs provenance invariants. | **Accepted.** `created_at_source` applies only when `created_source = 'filesystem'`; tests on a populated v3 store: sources preserved through section replacement and renames; cards, FTS, embeddings and events unchanged. |
| 15 | Low | Recency documentation and focused coverage lagged. | **Accepted, done** in the recency PR: `docs/design/search.md` both places, a default-off and configuration test; ADR-0007. |
