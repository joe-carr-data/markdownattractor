**Verdict:** "Ready with listed changes." Of B3–B12: B4, B5, B6, B8, B12 resolved; B3, B7, B9, B10, B11 partial. Of the first pass: F2, F4, F8, F15 resolved; the rest partial as listed below.

## New findings and triage

| # | Sev | Finding | Triage (plan, "Implementation scope") |
|---|---|---|---|
| C1 | High | Merge-only changes escape invalidation: `git log --name-only old..new` emits no merge diffs. | **Accepted.** The history walk uses `--diff-merges=separate` (not `--first-parent`, which would hide side-branch history). |
| C2 | High | The validated-commit checkpoint has no atomicity contract. | **Accepted.** Marking documents `needs` and advancing the checkpoint happen in one transaction; a failed or truncated listing marks every document and is treated like a non-ancestor. |
| C3 | Medium | Delegated `mda index` has no dating or skip protocol. | **Accepted, by cutting.** No `--no-git-times` flag (`time_source` covers it). A delegated `mda index` returns after indexing; the daemon's dating thread is notified and dates in the background; documented. |
| C4 | Medium | "Any failure" becomes terminal `filesystem`, swallowing retryable failures. | **Accepted.** Three outcomes: proven ineligible (`filesystem` at that commit and blob), snapshot mismatch (stays `needs`), operational failure (`failed`). |

## Remaining partials and what the first implementation does

| Finding | Decision |
|---|---|
| B3/F1 merges, checkpoint | C1, C2 above. |
| B7/F11 paths | Commands run with `-C <top level>`; history paths outside the root's prefix are dropped before any lookup; a document is matched to the tree by its exact, case-sensitive path, otherwise filesystem. |
| B9/F13 cost, retries | No retry timers: a `failed` document is retried when the commit changes or on the next explicit `mda index`. Slices in the daemon; a per-call timeout below the slice length. Batching of history walks deferred until measured. |
| B10/F3 contention | One short transaction per document from the dating thread; a test bounds an indexer write while a pass runs. Routing writes through the indexer is deferred. |
| B11 recovery | When discovery becomes usable again, `failed` and `filesystem` documents examined at another commit are requeued by the commit-change rule; with an unchanged commit they are requeued on the next explicit `mda index`. |
| F5 moved unique section | Stated: unchanged text keeps its date until the file is committed and re-dated. |
| F7 renames, restoration | A rename detected by the daemon inherits created time and source (existing behaviour, now with the source); `time_source = "filesystem"` restores file times on the next `mda index`. |
| F10 | The missing-final-newline test is back in the list; blame must cover every line of the file or the document is not dated. |
| `--follow` | Documented choice: created is the minimum over the followed history, including earlier incarnations and copies git follows. |

Cut suggested and **not** taken: daemon dating. The daemon is the default way the product runs, so it keeps a dating thread (start, after a rescan, on a commit change seen by a 30 s poll), without retry timers.
