| 1 | High | A finding could be stale when printed: its file edited while a later pair was judged; a status added to the other file's front matter passed the check; a deleted candidate aborted the review. | **Fixed.** A finding is provisional until `settle`, after the last call: both files must read exactly as when the pair was judged, else `stale_during_review`. At judgment time the other file must hold the section under the same heading **and** the front matter the judge was shown. A file that is gone is stale, not an error. Three tests (edit, delete, front matter). |
| 2 | High | The retry ignored the daily budget. | **Fixed.** The ledger is read before every attempt. A pair whose retry is refused is `failed` with both reasons; the run is `stopped`. Test with a billed malformed answer. |
| 3 | High | Stored paths went to `git hash-object` before any containment check; a vanished path could fail the batch. | **Fixed in part.** Only paths that are, at that moment, regular files under the root (`safe_join`, no symlink) are handed to git, and the changed file is read through `safe_join`. **Not closed:** the instant between that check and git's read. Hashing bytes the engine captured needs either one git process per file or a SHA-1 implementation (a new crate, so an ADR); recorded in the module docs and the backlog. |
| 4 | High | Every changed section kept its own copy of the file's text. | **Fixed.** One shared copy per file (`Arc<str>`). |
| 5 | Medium | A daemon re-indexing between the ranked search and the load could make a section id name another section. | **Fixed for the section:** a loaded section must have the hash and heading path of the hit that chose it. The document context is read later from the index; it is then checked against the file (front matter) before a finding stands. One SQLite read snapshot for all of it is **not** done. |
| 6 | Medium | Index membership was read as proof: an ignored tracked file was a "deleted file"; an unreadable new file vanished from the report; `index_root` can tombstone a row a daemon just created. | **Fixed** for the first two: `not_indexed` when the file exists, `unreadable` from the sync's own error list. **Deferred:** the tombstone race is `Engine::index_root`'s, older than this command, and affects `mda index` beside a daemon equally; backlog. |
| 7 | Medium | An `Err` from the backend lost the attempt and the report. | **Fixed.** The attempt is written to the ledger as `impact_error_usage_unknown`, the pair is `failed`, the run `stopped`, the remaining pairs `not_judged`. Test. |
| 8 | Medium | Spend could be booked under the configured model when another ran (the local backend). | **Fixed.** The ledger takes the model the backend's usage names, when it names one. |
| 9 | Medium | A pair too large to send used a judgment slot and was attributed to the changed section alone. | **Fixed.** The cap counts calls made; `too_large` names both files (`with`). Test. |
| 10 | Medium | Coverage the finder computed was dropped: linked documents cut, sections passed over, changes with no candidate. | **Fixed:** `searches_truncated` includes the linked-document limit; `cut_per_document` and `changes_without_candidates` are in the report and the human output. A full per-change search record (`examined` per change) is **not** added. |
| 11 | Medium | A backend that failed to initialise read as "no backend"; without a backend the candidates were only in `--all`/`--json`. | **Fixed.** The reason is in the report (`backend_note`) and in the summary line; without a backend the pairs are always listed. The command still exits 0: nothing was judged, and that is said. |
| 12 | Medium | A rate limit spent the retry at once. | **Fixed.** A pause (2 s) before the retry of a rate-limited call, then the budget check. |
| 13 | Low | Line-ending-only differences inflated `files_changed`. | **Fixed.** Only files with a change or an unpaired section count, plus new and deleted ones. Test. |
| 14 | Low | The human output re-spaced quotes; findings take several lines. | **Fixed** for the quote: the file's own text, a line break shown as `⏎`. Several lines per finding are kept on purpose, as for `search` hits: the passages are the output. `--json` carries the exact text. |
